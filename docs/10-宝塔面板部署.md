# 10 宝塔面板（BT Panel）部署

服务器的 web 入口由**宝塔的 Nginx** 负责，docker 里只跑 PHP 应用（以及可选的 MySQL / Redis）。

如果你还没部署过，先看 [08-GitHub部署与前端发布](08-GitHub部署与前端发布.md) 了解整体链路；代理头的原理看 [09-Nginx反向代理与请求头](09-Nginx反向代理与请求头.md)。本篇只讲**宝塔环境下的差异**。

---

## 1. 和纯 docker 方案的三个区别

| 项 | 纯 docker（08 文档） | 宝塔面板（本篇） |
|---|---|---|
| 80 端口谁监听 | docker 里的 `mineadmin-nginx` | **宝塔的 Nginx**（宿主机进程） |
| 前端静态文件 | 挂载给 docker nginx | 宝塔站点根目录直接指向 `MineAdmin/web` |
| `/prod` 反代 | `deploy/nginx/default.conf` | 宝塔站点配置文件里的 `location ^~ /prod/` |

关键点：**宝塔的 Nginx 装在宿主机上，容器里的 nginx 抢不到 80 端口**。所以要先关掉 docker 那个 nginx。

```
浏览器 :80/:443
   │
   ▼
宝塔 Nginx（宿主机 www 用户）
   ├─ /             → /opt/hyperfstu/MineAdmin/web
   ├─ /uploads/     → /opt/hyperfstu/MineAdmin/storage/uploads
   ├─ /static/      → /opt/hyperfstu/MineAdmin/web/static
   └─ /prod/*       → 127.0.0.1:9501  (docker 端口映射)
                          │
                          ▼
                    mineadmin-app（Swoole）
                          ├── mysql:3306   (docker 内网)
                          └── redis:6379   (docker 内网)
```

## 2. 前置检查

```bash
# 1) 80/443 被谁占用（应该是宝塔的 nginx）
ss -lntp | grep -E ':80|:443'

# 2) docker 和 compose 插件
docker --version
docker compose version

# 3) 宝塔自带的服务端口（避免和我们的映射冲突）
ss -lntp | grep -E ':3306|:6379'
```

宝塔没有 Docker 的话：面板 → 软件商店 → 搜「Docker管理器」安装；或者命令行装官方版（推荐，带 compose 插件）：

```bash
curl -fsSL https://get.docker.com | bash -s docker --mirror Aliyun
systemctl enable --now docker
docker compose version
```

我们的 compose 里 MySQL / Redis 映射到 `127.0.0.1:13306` / `127.0.0.1:16379`，和宝塔默认的 `3306` / `6379` 错开，**不会冲突**。

---

## 3. 第一步：关掉 docker 里的 nginx

本地改 `deploy/.env`：

```ini
USE_DOCKER_NGINX=0
WEB_PORT=80
APP_PORT=9501
```

第一次部署直接带上宝塔开关：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\bootstrap.ps1 -BtPanel
```

`-BtPanel` 会把 `USE_DOCKER_NGINX` 写成 0。之后 `update.sh` / `publish.ps1` 都不会再启动 docker nginx，并且会顺手 `rm -sf nginx` 清掉之前残留的容器，避免它继续占着 80。

已经部署过（`deploy/.env` 已存在）也不用重新 bootstrap，改完那行直接：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\remote.ps1 update
```

验证：

```bash
cd /opt/hyperfstu
docker compose -f deploy/docker-compose.yml ps
# 只应该有 app / mysql / redis，没有 nginx

curl -s -o /dev/null -w '%{http_code}\n' -X POST \
  -H 'Content-Type: application/json' -d '{}' \
  http://127.0.0.1:9501/admin/passport/login
# 期望 422（参数校验失败），说明后端活着
```

> 注意后端直连没有 `/prod` 前缀。`/prod` 是面板 Nginx 剥掉的。

---

## 4. 第二步：宝塔建站

面板 → 网站 → 添加站点：

| 项 | 填什么 |
|---|---|
| 域名 | 你的域名；没有域名可以先填服务器 IP 或随便一个临时域名 |
| 根目录 | 默认生成在 `/www/wwwroot/xxx`，**稍后改** |
| FTP | 不创建 |
| 数据库 | 不创建（我们用 docker 里的 MySQL） |
| PHP 版本 | **纯静态** |

建好后点「设置」：

1. **网站目录** → 目录改成 `/opt/hyperfstu/MineAdmin/web`，保存。
2. **网站目录** → 取消勾选「防跨站攻击(open_basedir)」（纯静态站点用不到 PHP，勾着也无害，但取消更省事）。
3. **伪静态** → 选「无」。哈希路由不需要 rewrite，写 `try_files` 反而可能把 `/prod` 抢走。

> 为什么必须选「纯静态」：如果交给 php-fpm，宝塔会用自己那套 PHP（没有 Swoole）去解析，而且 Hyperf 的 `public/index.php` 入口并不在这里。静态站 + 反代是正确的组合。

---

## 5. 第三步：加反向代理和 location

打开 `deploy/bt/nginx-site.conf`，把里面的内容复制出来，粘到宝塔站点配置文件里。

路径：网站 → 设置 → 配置文件。文件在 `/www/server/panel/vhost/nginx/<域名>.conf`。

也可以在服务器上直接看：`cat /opt/hyperfstu/deploy/bt/nginx-site.conf`。

**要粘在 `server { ... }` 内部**，不要整个替换 server 块（否则会丢掉宝塔自动生成的 SSL、日志、错误页配置）。

核心就这一条：

```nginx
location ^~ /prod/ {
    proxy_pass http://127.0.0.1:9501/;   # 尾斜杠必须写
    ...
}
```

三个必须注意的点：

### 5.1 尾斜杠

| 写法 | `/prod/admin/x` 转发成 | 结果 |
|---|---|---|
| `proxy_pass http://127.0.0.1:9501/;` | `/admin/x` | ✅ 正确 |
| `proxy_pass http://127.0.0.1:9501;` | `/prod/admin/x` | ❌ 全部 404 |

宝塔的「反向代理」界面生成的是**不带斜杠**的版本，所以用界面加完还要手动改一下，或者干脆像上面那样直接写配置。

### 5.2 用 `^~ /prod/`，不要用 `location /prod/`

宝塔站点配置里有这类默认规则：

```nginx
location ~ .*\.(gif|jpg|jpeg|png|bmp|swf)$ { expires 30d; }
location ~ /\. { deny all; }
```

`~` 是正则，优先级高于普通前缀匹配。请求 `/prod/admin/avatar.png` 会被图片规则抢走，直接去磁盘找文件 → 404。

`^~` 表示「前缀匹配成功后，不再尝试正则」，加了它才稳。

### 5.3 保存后确认 Nginx 真的重载了

宝塔保存配置时会自己跑 `nginx -t`，失败会弹错误并回滚。命令行复核：

```bash
/www/server/nginx/sbin/nginx -t
/www/server/nginx/sbin/nginx -s reload
```

看到 `syntax is ok` / `test is successful` 才算生效。

---

## 6. 第四步：给 `www` 用户读权限

宝塔的 Nginx worker 以 `www` 用户运行，而 `/opt/hyperfstu` 是 root 建的。目录本身是 755 的话通常没问题，遇到 403 就补一下：

```bash
chmod o+x /opt /opt/hyperfstu /opt/hyperfstu/MineAdmin
chmod -R o+rX /opt/hyperfstu/MineAdmin/web
chmod -R o+rX /opt/hyperfstu/MineAdmin/storage/uploads
```

如果开了 SELinux（宝塔机器一般没有）：

```bash
chcon -R -t httpd_sys_content_t /opt/hyperfstu/MineAdmin/web
```

## 7. 第五步：验证

按顺序验证三层，哪一层出问题一目了然。

**注意 `Host` 头**：宝塔站点是按 `server_name` 匹配的。服务器上往往不止一个站点，直接 `curl 127.0.0.1` 可能命中别的默认站点，所以要么带上 `Host`，要么直接用域名。

```bash
DOMAIN=你的域名   # 没有域名就填建站时用的那个 server_name

# ① 后端活着（容器直连，无前缀）
curl -s -o /dev/null -w '%{http_code}\n' -X POST -H 'Content-Type: application/json' \
  -d '{}' http://127.0.0.1:9501/admin/passport/login
# 422 = 正常（参数校验失败）

# ② 面板 Nginx 这一层（只看变量，不转发）
curl -s "http://127.0.0.1/__echo?x=1" -H "Host: $DOMAIN" -H 'X-Custom: hello'

# ③ 完整链路：面板 Nginx → 容器
curl -s "http://127.0.0.1/prod/admin/proxy/debug?page=2" -H "Host: $DOMAIN" -H 'X-Custom: hello'
```

第 ③ 步的期望结果：

```json
{
  "code": 200,
  "data": {
    "path": "/admin/proxy/debug",          // /prod 被剥掉了
    "query": { "page": "2" },
    "ip": {
      "x-real-ip": "你的公网IP",
      "remote_addr": "172.18.0.2",         // 宿主机 docker 网关
      "getClientIps": ["你的公网IP"]        // 中间件生效后是真实 IP
    },
    "headers": {
      "x-original-uri": ["/prod/admin/proxy/debug?page=2"],
      "x-forwarded-prefix": ["/prod"],
      "host": ["你的域名或IP"]
    }
  }
}
```

最后打开浏览器：`http://你的域名/` → `admin / 123456`。

> 宝塔的 Nginx 在宿主机上，`$remote_addr` 是真实客户端 IP，所以 `x-real-ip` 一定正确。

## 8. SSL / HTTPS

宝塔一键申请最省事：

1. 网站 → 设置 → SSL → Let's Encrypt → 申请（域名要解析到这台机器，且 80 端口可达）。
2. 打开「强制 HTTPS」。
3. 证书申请成功后，宝塔会往 `server` 块里加 `listen 443 ssl;`，我们粘的 `location` 段**不需要重复添加**，http / https 共用。

改两处配置：

```bash
# 1) 后端生成绝对 URL（上传附件返回的地址）要用 https
sed -i 's|^APP_URL=.*|APP_URL=https://你的域名|' /opt/hyperfstu/MineAdmin/.env

# 2) 让 Swoole 重启（.env 变化会被 watcher 捕获，也可以手动重启）
docker compose -f /opt/hyperfstu/deploy/docker-compose.yml restart app
```

前端**不用改**：`.env.production` 里 API 是相对路径 `/prod`，自动跟随页面协议。

如果遇到混合内容（Mixed Content）报错，说明 `APP_URL` 还是 `http://`，老附件的绝对地址没改过来。

## 9. 防火墙

三层都要放行：

1. **云厂商安全组**：80、443（22 保留）。
2. **宝塔面板 → 安全**：80、443。
3. **9501 不要放行**。它只绑 `127.0.0.1`，外部本来就访问不到，但别去加规则。
4. 13306 / 16379 也不要放行。需要连数据库时用 SSH 隧道：

```powershell
ssh -L 13306:127.0.0.1:13306 -p 22 root@服务器IP
# 然后本地连 127.0.0.1:13306
```

## 10. 用宝塔自带的 MySQL / Redis（可选）

默认方案是 docker 里跑 MySQL + Redis，隔离干净、不污染宝塔环境，**推荐初学者直接用**。

如果你想复用宝塔已有的服务（省内存），改 `MineAdmin/.env`：

```ini
DB_HOST=host.docker.internal
DB_PORT=3306
DB_DATABASE=mineadmin
DB_USERNAME=mineadmin
DB_PASSWORD=你的密码

REDIS_HOST=host.docker.internal
REDIS_PORT=6379
REDIS_AUTH=
```

`host.docker.internal` 已经在 compose 里通过 `extra_hosts: host-gateway` 配好，容器能解析到宿主机。

还需要在宝塔的 MySQL 里建库和授权（注意 host 用 `%`，因为容器源 IP 是 docker 网段）：

```sql
CREATE DATABASE `mineadmin` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'mineadmin'@'%' IDENTIFIED BY '强密码';
GRANT ALL PRIVILEGES ON `mineadmin`.* TO 'mineadmin'@'%';
FLUSH PRIVILEGES;
```

Redis 如果开了密码就填 `REDIS_AUTH`；宝塔默认 `bind 127.0.0.1` 且 `protected-mode yes`，容器连不上，需要改 `/www/server/redis/redis.conf`：

```conf
bind 0.0.0.0
protected-mode no
requirepass 强密码
```

改完 `systemctl restart redis`（或面板里重启）。

> 安全提醒：`protected-mode no` + 公网可达 + 无密码 = 高危。务必设置密码，并且云安全组不要放行 6379。

此时可以把 compose 里的 mysql / redis 两个服务注释掉，或者继续留着（不启动就行）：

```bash
docker compose -f deploy/docker-compose.yml up -d app
```

## 11. 日常发布

和 08 文档完全一样，不需要额外操作：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\publish.ps1 -Message "feat: xxx"
```

`update.sh` 会：

1. `git pull`
2. 必要时 `composer install`
3. `migrate --force`
4. 前端有变化就构建，并同步到 `MineAdmin/web`
5. `up -d app`（不碰 docker nginx）
6. **不 reload 宝塔 Nginx**——因为我们没改面板配置

只有你**改动 `deploy/bt/nginx-site.conf` 并重新粘到面板**时，才需要重载：

```bash
/www/server/nginx/sbin/nginx -t && /www/server/nginx/sbin/nginx -s reload
```

宝塔面板上点「保存」也会自动做这一步。

## 12. 常见问题

### 12.1 部署后 80 端口报 `address already in use`

docker nginx 还在跑。确认 `deploy/.env` 是 `USE_DOCKER_NGINX=0`，然后：

```bash
cd /opt/hyperfstu
docker compose -f deploy/docker-compose.yml rm -sf nginx
docker compose -f deploy/docker-compose.yml up -d app
```

### 12.2 首页 403

权限或路径问题：

```bash
ls -l /opt/hyperfstu/MineAdmin/web/index.html
ls -ld /opt/hyperfstu /opt/hyperfstu/MineAdmin
namei -l /opt/hyperfstu/MineAdmin/web/index.html   # 逐级看权限
```

多半是某一级目录缺 `o+x`。按第 6 节补权限。

### 12.3 首页 404 / 目录列表

网站目录没指向 `MineAdmin/web`，或者前端还没构建：

```bash
ls /opt/hyperfstu/MineAdmin/web/index.html
cd /opt/hyperfstu && bash deploy/update.sh --skip-pull
```

### 12.4 `/prod/admin/*` 全部 404

两个原因，按顺序查：

1. `proxy_pass` 没写尾斜杠 → 后端收到 `/prod/admin/...`
2. 用了 `location /prod/` 而不是 `location ^~ /prod/` → 被宝塔的正则规则抢先

两种都能在 `/prod/admin/proxy/debug` 的 `path` 字段里看出来：正确应该是 `/admin/proxy/debug`。

### 12.5 502 Bad Gateway

宝塔连不上 `127.0.0.1:9501`：

```bash
docker compose -f /opt/hyperfstu/deploy/docker-compose.yml ps
docker compose -f /opt/hyperfstu/deploy/docker-compose.yml logs --tail=100 app
ss -lntp | grep 9501
```

如果 `9501` 只有 `127.0.0.1` 而没有容器在听，说明 app 没起来（composer 没装完 / `.env` 数据库密码错 / MySQL 没 healthy）。

### 12.6 登录接口 404（但后端直连正常）

`MineAdmin/.env` 里 `SWAGGER_ENABLED=false`。MineAdmin 3.2 的路由靠 Swagger 注解扫描注册：

```bash
sed -i 's/^SWAGGER_ENABLED=.*/SWAGGER_ENABLED=true/' /opt/hyperfstu/MineAdmin/.env
docker compose -f /opt/hyperfstu/deploy/docker-compose.yml restart app
```

### 12.7 上传大文件 413

宝塔的 `nginx.conf` 里有一份全局 `client_max_body_size`（通常 50m），站点里覆盖即可——我们的片段已经写了 `100m`。同时确认 PHP 侧：

```bash
docker compose -f /opt/hyperfstu/deploy/docker-compose.yml exec app \
  php -i | grep -E 'upload_max_filesize|post_max_size'
```

### 12.8 发布后页面还是旧的

`index.html` 被缓存。我们的片段给 `/index.html` 加了 `no-cache`，如果宝塔另有缓存（比如开了「网站加速」/ CDN），要去对应位置清。

浏览器 `Ctrl+F5`，或者检查响应头：

```bash
curl -sI http://你的域名/index.html | grep -i cache-control
```

### 12.9 宝塔「反向代理」界面加的和手写配置有什么区别

界面的配置在 `/www/server/panel/vhost/nginx/proxy/<站点>/<名称>.conf`，被主配置 `include` 进来。两种都行，但界面生成的 `proxy_pass` 不带尾斜杠，需要手动补成 `http://127.0.0.1:9501/`。

为了避免「界面覆盖手写配置」，建议**只用一种**：要么全用界面，要么全写进主配置。我们的片段是主配置方案。

### 12.10 `nginx: [emerg] unknown directive` 或 `map` 报错

`map` 只能写在 `http { }` 里，**不能写进 `server { }`**。我们的片段没有用 `map`（WebSocket 那两行已注释说明）。如果你手动加了，请挪到 `/www/server/nginx/conf/nginx.conf` 的 `http` 块内。
