# 01 线上部署 + 本地同步 + 热更新

> **新版流程请看 [08-GitHub部署与前端发布](08-GitHub部署与前端发布.md)。**
> 当前代码已经改成「GitHub 单仓库 + 服务器 git pull + Nginx 前端」的结构；本文保留为 tar 覆盖同步的原理说明，
> 其中 `/opt/mineadmin` 目录、9501 端口、`bootstrap.ps1` 的同步步骤已被 08 取代。
> `sync.ps1 -Watch` 仍可用于不提交的快速草稿。

目标：本地（Windows）改代码，保存后 1~3 秒线上生效，不用手动重启、不用手动上传。

## 0. 先看懂整条链路

```
┌────────────── 本地 Windows ──────────────┐        ┌────────────── Linux 服务器 ──────────────┐
│                                          │        │                                          │
│  VSCode 编辑 MineAdmin\app\...           │        │  /opt/mineadmin                          │
│        │                                 │        │   ├─ app/ config/ plugin/ ...            │
│        │ 保存                            │        │   ├─ .env                                │
│        ▼                                 │  SSH   │   ├─ vendor/        （容器里 composer）  │
│  sync.ps1 -Watch                         │───────▶│   └─ deploy/docker-compose.yml           │
│  （检测 mtime，tar 打包，scp 上传）      │  tar   │                                          │
│                                          │        │        │ 挂载 ../ → /opt/www             │
│                                          │        │        ▼                                 │
│                                          │        │  mineadmin-app 容器                      │
│                                          │        │   php bin/hyperf.php server:watch        │
│                                          │        │        │ 每 2 秒扫描 app/ config/ .env   │
│                                          │        │        ▼                                 │
│                                          │        │   Swoole 重启 → 9501 生效                │
└──────────────────────────────────────────┘        └──────────────────────────────────────────┘
```

同步是**覆盖式**的：本地有什么，服务器就有什么；本地删掉的文件，服务器也会删。
`vendor/`、`runtime/`、`web/` 不同步。

## 1. 服务器准备

### 1.1 配置建议

- Ubuntu 22.04 / Debian 12，2 核 2G 起（MySQL + Redis + PHP 三个容器）
- 磁盘 10G 以上（镜像约 500MB，vendor 约 200MB）
- 安全组/防火墙放行：`22`（SSH）、`9501`（应用）
- **不要**把 3306 / 6379 暴露到公网，compose 里已经只绑定 `127.0.0.1`

### 1.2 安装 Docker

```bash
# 官方脚本（国内服务器如果慢，先配镜像加速，见下）
curl -fsSL https://get.docker.com | sh

# 验证
docker version
docker compose version
```

国内服务器建议配置镜像加速（阿里云控制台有专属地址）：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "registry-mirrors": ["https://你的ID.mirror.aliyuncs.com"]
}
EOF
sudo systemctl restart docker
```

### 1.3 防火墙

```bash
# ufw 示例
ufw allow 22/tcp
ufw allow 9501/tcp
ufw enable
```

## 2. 配置 SSH 免密（Windows）

脚本会反复执行 `ssh` / `scp`，强烈建议用密钥。

```powershell
# 1. 生成密钥（已有可跳过）
ssh-keygen -t ed25519 -C "mineadmin-learn"

# 2. 把公钥写到服务器（会要求输入一次密码）
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@你的服务器IP "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

# 3. 验证（不再输密码就对了）
ssh root@你的服务器IP "echo ok"
```

如果服务器 SSH 不是 22 端口，第 2 步加 `-p 端口`。

## 3. 一键部署

### 3.1 填写配置

```powershell
cd D:\code\hyperfstu
Copy-Item scripts\deploy.config.example.ps1 scripts\deploy.config.ps1
notepad scripts\deploy.config.ps1
```

至少要改：

```powershell
$RemoteHost = '你的服务器IP'
$RemoteUser = 'root'
$RemotePath = '/opt/mineadmin'
$IdentityFile = 'C:\Users\Administrator\.ssh\id_ed25519'   # 或留空用默认密钥
```

### 3.2 执行

```powershell
powershell -ExecutionPolicy Bypass -File scripts\bootstrap.ps1
```

脚本会做 8 件事：

1. 检查 SSH 和 `docker compose`
2. 生成 `deploy/.env`（随机数据库密码，只生成一次）
3. 把本地 `MineAdmin` 代码同步到 `/opt/mineadmin`
4. 生成服务器 `.env`（随机 JWT 密钥；`APP_DEBUG=true`；**`SWAGGER_ENABLED=true`**）
5. 上传 `deploy/docker-compose.yml`
6. `docker compose pull` + 启动 MySQL/Redis，等健康检查通过
7. 容器内 `composer update`（第一次 3~10 分钟，取决于网速）
8. `php bin/hyperf.php mine:install` 执行迁移和种子数据，然后 `up -d app`

成功后会打印访问地址和默认账号 `admin / 123456`。

> 第一次 `composer update` 用的是 `update` 而不是 `install`：仓库里的 `composer.lock` 还是 3.1 的包版本，和 `composer.json` 的 `3.2.*` 对不上，直接 install 会报错。这个问题在文档 05 里有说明。同步脚本也刻意**不同步 composer.lock**，依赖版本以服务器实际解析结果为准。

### 3.3 验证

```powershell
# 首页
curl.exe http://你的服务器IP:9501/

# 登录（拿 token）
curl.exe -X POST http://你的服务器IP:9501/admin/passport/login ^
  -H "Content-Type: application/json" ^
  -d "{\"username\":\"admin\",\"password\":\"123456\"}"
```

返回示例：

```json
{
  "code": 200,
  "message": "成功",
  "data": {
    "access_token": "eyJ0eXAiOiJKV1Qi...",
    "refresh_token": "eyJ0eXAiOiJKV1Qi...",
    "expire_at": 3600
  }
}
```

如果 `/` 是 200 但 `/admin/passport/login` 是 404，先查 `.env` 里的 `SWAGGER_ENABLED` 是否为 `true`（原因见下一节）。

## 4. 为什么必须 `SWAGGER_ENABLED=true`

MineAdmin 3.2 的控制器没有 `#[Controller]`，只有：

```php
#[OA\HyperfServer(name: 'http')]
final class PassportController extends AbstractController
{
    #[Post(path: '/admin/passport/login', ...)]
    public function login(PassportLoginRequest $request): Result
```

路由注册发生在 `vendor/hyperf/swagger/src/Listener/BootSwaggerListener.php`：

```php
$config = $this->container->get(ConfigInterface::class);
if (! $config->get('swagger.enable', false)) {
    return;              // ← 关掉 swagger，路由也不会注册
}
...
$factory->getRouter($serverAnnotation->name)->addRoute(
    [$opera->method],
    $opera->path,
    [$class, $method],
    ['middleware' => ...]
);
```

`config/autoload/swagger.php` 里 `enable => env('SWAGGER_ENABLED', false)`。
所以：

- 学习/开发：`SWAGGER_ENABLED=true`
- 哪怕上生产：目前也必须 `true`，否则接口全 404（这是这份代码的实现方式，不是配置错误）
- `SWAGGER_ENABLED=true` 会额外监听 9503 端口（compose 没暴露，无影响）

## 5. 日常开发循环

准备两个 PowerShell 窗口：

**窗口 A：自动同步**

```powershell
cd D:\code\hyperfstu
powershell -ExecutionPolicy Bypass -File scripts\sync.ps1 -Watch
```

看到 `同步完成` 就说明这一轮改动已上传。

**窗口 B：实时日志**

```powershell
cd D:\code\hyperfstu
powershell -ExecutionPolicy Bypass -File scripts\remote.ps1 logs
```

然后：

1. 改 `MineAdmin\app\Http\Admin\Controller\PassportController.php` 里的 `summary` 或返回值
2. 保存
3. 窗口 A 打印同步完成
4. 窗口 B 出现 Hyperf 重启日志（约 2 秒后）
5. 浏览器/curl 立刻看到新结果

手动同步一次：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\sync.ps1
```

只同步 `.env`：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\sync.ps1 -IncludeEnv
```

> 默认不同步 `.env`，避免本地配置覆盖服务器配置。改 `.env` 后要手动加 `-IncludeEnv`。

## 6. 热更新到底怎么工作

配置文件：`MineAdmin/config/autoload/watcher.php`

```php
return [
    'driver' => ScanFileDriver::class,
    'bin' => 'php',
    'watch' => [
        'dir' => ['app', 'config'],
        'file' => ['.env'],
        'scan_interval' => 2000,
    ],
];
```

- 用的是 `ScanFileDriver`（轮询），**不需要 inotify 扩展**，所以在 Docker 里也能用
- 每 2000ms 扫一次 `app`、`config` 目录和 `.env`
- 有变化就 kill 旧进程并 `php bin/hyperf.php start`
- 重启会重新生成注解/AOP 代理（`runtime/container/proxy`），所以新增控制器、改注解都能生效

`server:watch` 的启动命令就是 compose 里 app 的 command：

```yaml
command: ["php", "bin/hyperf.php", "server:watch"]
```

### 热更新的边界

| 改动 | 是否自动生效 | 说明 |
|---|---|---|
| `app/**` 里的 PHP | ✅ | 2 秒内 |
| `config/**` 里的 PHP | ✅ | 2 秒内 |
| `.env` | ✅ | 需要 `-IncludeEnv` 同步 |
| `composer.json` 加依赖 | ❌ | 要在服务器执行 `remote.ps1 install` |
| `databases/migrations` | ❌ | 要执行 `remote.ps1 migrate` |
| 前端 `web/` | ❌ | 前端单独构建，见文档 06 |
| `vendor/` 源码 | ❌ | 不要本地改 vendor |

### 关掉/调整热更新

- 生产环境把 compose 的 command 改成 `["php", "bin/hyperf.php", "start"]`
- 觉得重启太频繁，把 `scan_interval` 调大，或把 `watch.dir` 收窄

## 7. `.env` 关键项

服务器文件：`/opt/mineadmin/.env`（权限 600）

| 变量 | 学习环境值 | 说明 |
|---|---|---|
| `APP_ENV` | `dev` | dev 下 migrate 不二次确认 |
| `APP_DEBUG` | `true` | 关闭 scan_cacheable，worker_num=1，方便调试 |
| `SWAGGER_ENABLED` | `true` | **必须**，否则没有路由 |
| `SWAGGER_AUTO_GENERATE` | `false` | 生成 OpenAPI json，学习时不需要 |
| `DB_HOST` | `mysql` | compose 服务名 |
| `DB_PASSWORD` | 随机 | 与 `deploy/.env` 的 `DB_ROOT_PASSWORD` 一致 |
| `REDIS_HOST` | `redis` | compose 服务名 |
| `JWT_SECRET` | 随机 base64 | 换掉后旧 token 全部失效 |
| `APP_URL` | `http://服务器IP:9501` | 生成回调/文件 URL 时会用 |

改完 `.env`：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\sync.ps1 -IncludeEnv
```

或者直接改服务器：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\remote.ps1 shell
# 容器内： vi /opt/www/.env
```

## 8. 常用命令

```powershell
# 容器状态
powershell -ExecutionPolicy Bypass -File scripts\remote.ps1 ps

# 重启 app
powershell -ExecutionPolicy Bypass -File scripts\remote.ps1 restart

# 进容器
powershell -ExecutionPolicy Bypass -File scripts\remote.ps1 shell

# 执行任意命令
powershell -ExecutionPolicy Bypass -File scripts\remote.ps1 exec -Command "php bin/hyperf.php list"

# 迁移 / 种子
powershell -ExecutionPolicy Bypass -File scripts\remote.ps1 migrate
powershell -ExecutionPolicy Bypass -File scripts\remote.ps1 seed

# 重装依赖 + 重新初始化（危险：会重新 migrate/seed）
powershell -ExecutionPolicy Bypass -File scripts\remote.ps1 install

# tinker（交互式）
powershell -ExecutionPolicy Bypass -File scripts\remote.ps1 tinker
```

服务器上直接操作：

```bash
cd /opt/mineadmin
docker compose -f deploy/docker-compose.yml ps
docker compose -f deploy/docker-compose.yml logs -f --tail=200 app
docker compose -f deploy/docker-compose.yml exec app sh
```

## 9. 从本地连服务器数据库（可选）

数据库只监听服务器 `127.0.0.1:13306`，用 SSH 隧道：

```powershell
ssh -N -L 13306:127.0.0.1:13306 root@你的服务器IP
```

然后本地 Navicat / DBeaver 连 `127.0.0.1:13306`：

- 用户：`root`
- 密码：`deploy/.env` 里的 `DB_ROOT_PASSWORD`
- 库：`mineadmin`

Redis 同理：`ssh -N -L 16379:127.0.0.1:16379 root@IP`，本地连 `127.0.0.1:16379`。

## 10. 生产模式和学习的区别

学习阶段用的是"开发模式"，真上线要改：

| 项 | 学习 | 生产 |
|---|---|---|
| 启动命令 | `server:watch` | `start` |
| `APP_DEBUG` | `true` | `false` |
| `worker_num` | 1（由 APP_DEBUG 决定） | CPU 核数 |
| 注解缓存 | 关闭（每次扫描） | 开启（`scan_cacheable=true`） |
| 前端 | 可不部署 | `web/` 放构建产物，Nginx 托管 |
| 入口 | 直接 9501 | Nginx → 9501，只暴露 80/443 |
| 数据库/Redis | 本机 127.0.0.1 | 独立实例 + 强密码 + 备份 |
| 日志 | `runtime/logs/*.log` | 集中收集 + 轮转 |

> 注意：即使生产，当前版本仍需 `SWAGGER_ENABLED=true`，但建议限制 9503 端口只对本机开放，或用防火墙拦掉。

## 11. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `bootstrap` 卡在 SSH | 密码/密钥错误、端口错 | 先 `ssh root@IP "echo ok"` 手动验证 |
| `docker compose pull` 很慢/失败 | 没配镜像加速 | 配 `daemon.json` 后重启 docker |
| `composer update` 报 memory exhausted | 容器内存不足 | 服务器加 swap，或 `COMPOSER_MEMORY_LIMIT=-1` |
| app 容器反复重启 | `.env` 缺失、vendor 没装 | `remote.ps1 logs` 看具体报错，重跑 `bootstrap` |
| 所有 `/admin/*` 404 | `SWAGGER_ENABLED=false` | 改 `.env` 为 true，`sync -IncludeEnv` |
| `Class "Redis" not found` | 镜像/扩展问题 | 用部署脚本指定的 hyperf 官方镜像 |
| `runtime` 写入失败 | 目录权限 | 容器内是 root，一般不会；宿主机目录被改权限时 `chmod -R 777 runtime` 仅限学习环境 |
| 改了代码没反应 | watch 没开、同步没跑 | 确认 `docker compose ps` 里 app 是 Up，窗口 A 有输出 |
| 登录返回 500 | 数据库没初始化 | `remote.ps1 install` 或 `migrate` + `seed` |
| 登录 422 `password_error` | 种子数据没跑/密码错 | 默认 `admin/123456`，重跑 seed |
| `composer update` 报数据库密码错误 | `deploy/.env` 被改过，但 MySQL 数据卷还是旧密码 | 找回旧密码，或 `down -v` 重置（会清空数据）后重新 `bootstrap` |
| 端口 9501 被占用 | 服务器已有服务 | 改 `deploy/.env` 的 `APP_PORT`，重新 `bootstrap -Force` 或手动 `up -d` |

看容器内 PHP 报错：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\remote.ps1 logs
powershell -ExecutionPolicy Bypass -File scripts\remote.ps1 exec -Command "tail -n 100 runtime/logs/debug.log"
```

## 12. 重置环境

```powershell
# 停止并删除容器（保留数据卷）
powershell -ExecutionPolicy Bypass -File scripts\remote.ps1 down

# 连数据一起删（重新初始化）
ssh root@你的服务器IP "cd /opt/mineadmin && docker compose -f deploy/docker-compose.yml down -v"
powershell -ExecutionPolicy Bypass -File scripts\bootstrap.ps1
```
